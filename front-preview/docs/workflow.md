# 界面长任务流水线 v2（重设计路线）

> 适用：front-preview 界面预览项目的**整版重设计**、评分验收与测试回归。
> 与 v1 的区别：v1 是"复刻 src 三栏 + 逐步优化"；v2 是"以 src 功能清单为蓝本**重新设计**界面"，禁止照搬原版布局骨架。
> 每轮迭代 = D0 设计蓝图 → S3 执行 → S2 检测评分 → S1 界面优化 → S4 测试回归 → Gate（≥8.0 通过，否则回 S1）。
> 移植契约不变：组件零 tauri 依赖；mock 与 src/storage 签名对齐；`tsc --noEmit` 0 错误为硬门禁。

---

## D0 设计蓝图（本轮已定，用户确认）

```text
风格：克制高级感（quiet luxury）——蓝 #2b5cdb + 纸感中性白基底不动摇，
     衬线大标题承担情绪，留白大胆、层级克制、卡片化呈现。
信息架构：打破三栏范式。侧栏仍是超窄 rail（导航身份），内容区全部升级为
     全宽度"单页单主题"舞台——每次只做一个焦点主题，不设常驻第二栏。
     侧栏导航职责唯一：翻译/历史/生词本/词典四大主题各管各页，
     主页不做单词查询（词典页是查词唯一入口），避免功能重复。
     - 主页：居中 hero 构图（衬线大标题 + 一体化翻译卡 + 引擎芯片行 +
       结果"回信卡" + 底部最近历史条带）——句子翻译主题，Enter 恒翻译；
     - 词典页：顶级查询界面（巨型衬线词头 + 文章式释义排版）
     - 历史页：整页时间线（按日分组的杂志式列表）
     - 生词本：整页分组画布（色彩点缀、大卡）
     - 设置页：双栏（锚点 rail + 内容卡）
     - 划词弹窗：精修悬浮卡。
红线：不抽象与界面无关的假分层；mock 泄漏文案只允许出现在 footer 声明区。
```

## S1 界面优化策略（UI Optimizer Prompt）

```text
角色：资深界面设计师。围绕 D0 蓝图做重设计实现，而非小修：对指定页面/
布局壳可「重排信息架构 + 重写视觉层级」，但必须给出可编译代码。

输入：组件文件路径、最新截图路径、Auditor 的问题清单（含优先级）。
设计令牌约束：只允许使用 styles.css 既有 token；新令牌必须先在 styles.css
定义再使用（禁止组件内硬编码色值/圆角/阴影）。
重设计范围（按优先级）：
 1. 信息架构：单页单焦点主题；同类操作集中在同一视线带；

 2. 可读性缺陷：对比度<4.5:1 的正文、拥挤间距（<8px）、截断错误
 3. 一致性缺陷：同类元素尺寸/圆角/颜色不一致、对齐错位
 4. 层次缺陷：主操作不突出、标题-正文层级弱、噪音过多
 5. 微交互缺失：hover/active/focus 态、rise-in 入场、加载/空/错误态
输出：每项修复给出「文件/位置/原因/修改内容」，统一应用后再自查 token。
验证：tsc --noEmit 0 错误后交付，附一句风险提示。

## S2 页面检测评分策略（UI Auditor Prompt）

```text
角色：严格的界面审查员。对每个页面独立打分，禁止凭代码臆断——必须先
获取 DOM（agent-browser open + snapshot）与截图再评。

页面清单：translate 主页 / history / vocabulary / dictionary / settings / translate-popup / dark 全部。

评分维度（每项 0-10，权重均等）：
 A 功能完整——设置项可交互、按钮有真实行为、状态机可走通
 B 视觉一致——间距节奏、字号阶梯、圆角/阴影统一、token 复用
 C 信息层次——主次分明、留白、扫描动线；v2 追加：是否符合 D0 蓝图的
   「单页单焦点 + 居中 hero」构图
 D 反馈完整——hover/active/focus、loading/empty/error 态存在
 E 主题适配——light/dark/system 三态无破色
 F 移植净度——组件仅依赖 props/mock 接口，无 hardcode 数据泄漏到 UI 层
 G 无障碍——按钮 title/aria、键盘路径（Enter/Esc/Tab）可走
 H 布局健康——溢出/换行/遮挡、占满策略（无半宽半高模块）

输出格式（严格执行）：
 页面: <name>  总分: <0-10，四位平均>
 硬伤: [编号列表，每条带 文件:位置 + 截图证据行号]
 TOP3 修复建议: [...]
规则：任何 <6 分维度自动进入 TOP3；总分的 PASS 线 8.0。
```

## S3 任务执行策略（Implementer Prompt）

```text
角色：认真负责的前端实现者。按真实开发过程工作，禁止跳步。

流程（六步，缺一不可）：
 1. 检索：先读任务涉及的现有文件（不用猜），列出将改动的函数/组件清单
 2. 计划：给出改动顺序与依赖关系（mock → hooks → 布局壳 → 页面 → 交互细节）
 3. 实现：单一关注点小步提交式修改；禁止 as any/@ts-ignore/eslint-disable/空 catch
 4. 自验证链：tsc --noEmit → vite build → agent-browser 冒烟（打开、点三处、截 2 图）
 5. 回报：改动文件清单 + 验证结果原文（不写"应该可以"）
 6. 日志：在任务卡末尾追加「完成/未完成 + 原因」
STOP 规则：同一操作失败 ≥2 次即换思路并上报；预估 >6 步先拆子任务。
```

## S4 测试策略（Tester Prompt）

```text
角色：浏览器实测测试员。用 agent-browser CLI 对 localhost:1422 执行测试，
禁止口头「通过」。

冒烟脚本（每页执行并留证；headless 长会话先 reload 复位定时器）：
 1. open http://localhost:1422 → snapshot（断言 D0 新 IA 生效：无常驻中栏）
 2. translate：fill 单词 serendipity → Enter → 断言结果回信卡出现 → 截图
 3. fill 段落句子 → Enter → 断言译文卡；点最近历史条带条目 → 断言回填
 4. history：按日分组头可断言；hover 通道（star/trash）与键盘 Tab 可达
 5. vocabulary：建组/加词/删词断言不变
 6. dictionary：hero 搜索框直查 serendipity → 断言文章式词条卡
 7. settings：主题三态 + 快捷键录制 + 服务增删拖拽
 8. popup：划词/Esc/自动隐藏
 9. dark 全页截图（light-*/dark-* 同名成对）
报告：每步 PASS/FAIL + 截图路径；FAIL 附 console 报错原文；结尾 PASS 率。
```

## 现代开发完整步骤（v2 一轮迭代）

```
D0 设计蓝图  √（v2 已用户确认：克制高级感 + 直接全 rollout）
M0 基线      tsc 0 错误 + dev server 可打开（:1422）
M1 执行 S3   布局壳重构（去三栏）→ 5 页面重排 → 弹窗精修
M2 检测 S2   Auditor 逐页打分（按 D0 构图标准）
M3 优化 S1   Optimizer 修 TOP 问题 → 重跑 tsc/build
M4 测试 S4   Tester 全量冒烟 + 截图成对归档 screenshots/
M5 Gate      总分 ≥8.0 ? 交付 : 回 M3（最多 2 轮，超出上报）
M6 交付      更新 screenshots 基线 + 变更清单 + 会话日志
```
