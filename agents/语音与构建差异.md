# agents/构建差异与 TTS 门控（双架构 / moss-tts）

> 触发时机：涉及 Intel/x86_64 构建、moss-tts-nano、ort-sys、语音命令时读取本文件。

## Intel 版本为何要门控 moss-tts

- `moss-tts-nano` 传递依赖 `ort-sys`（ONNX Runtime）**没有 x86_64-macos 预编译库**，Intel 构建必失败（错误形态：`no prebuilt binaries available for target x86_64-apple-darwin`）
- 门控方式（勿随意改动）：
  - `src-tauri/Cargo.toml`：moss-tts-nano 移到 `[target.'cfg(not(all(target_os = "macos", target_arch = "x86_64")))'.dependencies]`
  - `src-tauri/src/commands/mod.rs`：`pub mod tts;` 同 cfg 门控
  - `src-tauri/src/lib.rs`：`TtsEngineCache` manage 与 6 个 tts 命令注册逐条同 cfg 门控
- 前端零改动即可降级：MOSS VoiceSection 设置分节本就注释停用；TTSButton 走系统 `speechSynthesis`；ttsCache/prewarm 对命令缺失静默 catch

## 改 moss-tts 相关代码的两架构验证

```bash
cargo check && cargo check --target x86_64-apple-darwin
```

任何新增依赖（尤其带 C/预编译产物的 crate）都需双 target 验证，避免重蹈 ort-sys 覆辙。
