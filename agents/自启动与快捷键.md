# agents/自启动与快捷键（keyboard-hook / LaunchAgent / 事件 tap）

> 触发时机：改动自启动、快捷键、keyboard-hook 子进程、全局按键监听相关代码时读取本文件。

## 自启动链路

- `tauri-plugin-autostart`（MacosLauncher::LaunchAgent，args `["--hidden"]`），lib.rs setup 注册
- LaunchAgent plist：`~/Library/LaunchAgents/Desktop Translation.plist`，ProgramArguments = .app 内主二进制 + `--hidden`，RunAtLoad
- lib.rs setup **末尾**处理 `--hidden`：隐藏主窗口仅留托盘（必须晚于 window-state 恢复，否则藏不住）
- 「登录项」在系统设置 → 通用 → 登录项 / Release 页可见，可交叉验证

## keyboard-hook PING/PONG 心跳协议（勿破坏）

background：登录早期 launchd 拉起 app 时事件 tap（CGEventTap）可能创建过早而失灵——子进程**活着但收不到按键**（try_wait 看不出的假活），曾致「自启动后快捷键不响应、需重设才恢复」。

- 子进程 `src-tauri/src/bin/keyboard_hook.rs`：stdin 收到 `PING` → stdout 立即回 `PONG`（独立 heartbeat 线程）
- 主进程 `src-tauri/src/app/keyboard_hook.rs`：
  - 子进程 spawn 时 `stdin(Stdio::piped())`，句柄随 `HookChild { child, stdin }` 存在 `KeyboardHookProcess` state
  - stdout 读取线程识别 `PONG` 更新 `HookPingTracker`（两个 Arc<AtomicU64>：sent / seen）
  - 看门狗每 3s 三级判定：进程已退出 → 重建；上一轮 PING 无 PONG（假活）→ kill + 重建并带连败退避（每 5 次失败歇 30s）；健康 → 发新一轮 PING
- 改动守则：main 侧的事件行过滤只认 `TRANSLATE`/`SHOW_MAIN` 开头，`PONG` 单独处理；勿让 hook stdout 输出其他内容（会被误当事件）
- 事件格式：hook 输出 `TRANSLATE {cursor_x} {cursor_y}` 触发划词翻译；快捷键匹配逻辑：先按 modifier（ctrl/meta/shift/alt 4 位）再按按键序列（500ms 窗口内连击）

## Permissions 依赖

- keyboard-hook（rdev）需要 macOS「辅助功能/输入监视」授权；授权绑定代码签名身份
- 增量更新若重签会**清掉授权**（用户需重新授权），全量替换同签名 .app 不影响
