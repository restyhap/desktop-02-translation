# agents/文件同步（GitHub / Gitee / Releases / 版本发布）

> 触发时机：涉及发布、版本号变更、Release 操作、GitHub/Gitee 同步、dmg 打包时读取本文件。

## 一键发布

```bash
bash release.sh        # 仓库根
```

覆盖全流程（脚本内自校验）：
1. 读版本号（`src-tauri/tauri.conf.json` 的 `version`）
2. 双架构构建：`pnpm tauri build`（aarch64）+ `pnpm tauri build --target x86_64-apple-darwin`（Intel）
3. 推 main + tags 到 origin（GitHub）与 gitee 双远端
4. GitHub Release 创建/复用 + 资产幂等上传（已上传自动跳过）
5. Gitee Release 创建/复用 + attach_files 上传（文件名去空格）
6. 从 Gitee 实测下载 aarch64 dmg 校验 sha256

**版本号变更**需同步三处：`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml`（版本检查 `grep -rn '0.1.' 与旧号对照`）。

## 凭据（勿提交进仓库）

- 存放：`~/.config/release-tokens/desktop-translation.env`（chmod 700 目录 / 600 文件）
  - `GH_TOKEN`：github_pat_…（亦可已被 `gh auth login` 存入系统 keyring，`gh` 命令直接可用）
  - `GITEE_TOKEN`：gitee 个人访问令牌（projects 权限）
- 文件不存在时：提示用户在 gitee.com → 设置 → 私人令牌 与 github.com → Developer settings → Fine-grained tokens 自行生成并写入该文件。

## 双平台 Release 现状与地址

- GitHub: https://github.com/restyhap/desktop-02-translation （origin，公开）
- Gitee: https://gitee.com/restyhap/desktop-02-translation （gitee，公开；**私有则 release 附件 403 不可分发**，Gitee 私有仓库连带 token 的下载端点也不认）
- v0.1.1 起双平台均有 `DesktopTranslation_{版本}_{aarch64|x64}.dmg` 双资产。

## Release 平台 API 要点（手写调用时的坑）

- GitHub：REST `POST /repos/{owner}/{repo}/releases` 建发行版；`uploads.github.com` 传资产须 `Content-Type: application/octet-stream`；文件名**去空格**（带空格 curl 处理易失败）
- Gitee：`api/v5`；建 release 必带 `target_commitish=main`（否则报 "target_commitish is missing"）；传资产端点是 **`attach_files`（下划线，单数参数 `file`，一次一发）**；**无单资产删除端点**——上传错了只能删整个发行版重建
- 推 tag 后 Gitee 会按 tag 自动建出空发行版：发布脚本优先复用该 id，勿重复创建
- 校验可比 sha256：`shasum -a 256`（dmg 构建非确定性：同一版本两次构建大小/哈希会差几个字节，跨平台比对须比「同一次构建产物」）

## 数据无损原则（升级/替换应用时）

用户数据全部在 app 包外，替换 `/Applications` 里的 .app 不丢任何数据：
- SQLite（设置/历史/词库）、`settings.json`：`~/Library/Application Support/<bundle-id>/`
- LaunchAgent 登录项：`~/Library/LaunchAgents/Desktop Translation.plist`（ProgramArguments 指向 .app 内主二进制 + `--hidden`；路径不变即持续生效）
