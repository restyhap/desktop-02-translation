# 数据库设计文档
## 项目：Desktop Translation（桌面翻译软件）
**文档日期**：2026-09-09  
**设计版本**：v0.1 (MVP) → v0.3 (完整功能)

---

## 1. 设计原则

1. **与 mock 数据 1:1 对应**：确保 v0.1 迁移无代码逻辑变动
2. **Tauri 原生友好**：单文件、无服务器进程、易备份
3. **JSON 设计留白**：配置类字段统一 JSON 存储，结构演进无迁移痛点
4. **安全优先**：API Key 必须加密存储，支持主密码保护
5. **可扩展性**：预留字段给 v0.2-v0.3 功能扩展

## 2. SQLite Schema 设计

### 2.1 完整 Schema

```sql
-- 1. 翻译历史表
-- 对应：mockTranslations + HistoryList 搜索/收藏/时间轴
CREATE TABLE IF NOT EXISTS translation_history (
  id TEXT PRIMARY KEY,
  source_text TEXT NOT NULL,
  translated_text TEXT NOT NULL,
  source_lang TEXT NOT NULL CHECK(source_lang IN ('zh','en','ja','ko','fr','de','es','ru')),
  target_lang TEXT NOT NULL CHECK(target_lang IN ('zh','en','ja','ko','fr','de','es','ru')),
  engine TEXT NOT NULL DEFAULT 'google',
  timestamp INTEGER NOT NULL DEFAULT (CAST(strftime('%s','now') AS INTEGER)),
  favorite INTEGER NOT NULL DEFAULT 0,
  source_text_hash TEXT, -- md5(source_text)，用于去重
  access_count INTEGER NOT NULL DEFAULT 0, -- 访问计数，用于"最常用"展示
  last_accessed INTEGER -- 最后访问时间戳
);

-- 2. 词典表
-- 对应：mockDictionaries + DictionaryPanel 查询
CREATE TABLE IF NOT EXISTS dictionaries (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  format TEXT NOT NULL DEFAULT 'mdx' CHECK(format IN ('mdx','stardict','dsl')),
  path TEXT NOT NULL, -- 本地文件绝对路径
  word_count INTEGER NOT NULL DEFAULT 0,
  enabled INTEGER NOT NULL DEFAULT 1, -- 0=禁用, 1=启用
  last_updated INTEGER NOT NULL DEFAULT (CAST(strftime('%s','now') AS INTEGER)),
  file_size INTEGER -- 文件大小，用于显示/警告
);

-- 3. 词组表
-- 对应：mockVocabularyGroups + VocabularyPanel 分组切换
CREATE TABLE IF NOT EXISTS vocabulary_groups (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  color TEXT NOT NULL DEFAULT '#3b82f6', -- Tailwind color格式 (hex字符串)
  created_at INTEGER NOT NULL DEFAULT (CAST(strftime('%s','now') AS INTEGER))
);

-- 4. 词条表
-- 对应：mockVocabularyWords + VocabularyPanel 词频展示
CREATE TABLE IF NOT EXISTS vocabulary_words (
  id TEXT PRIMARY KEY,
  word TEXT NOT NULL,
  translation TEXT NOT NULL,
  phonetic TEXT, -- 可空
  example TEXT, -- 可空
  group_id TEXT NOT NULL, -- 外键引用 vocabulary_groups.id
  created_at INTEGER NOT NULL DEFAULT (CAST(strftime('%s','now') AS INTEGER)),
  review_count INTEGER NOT NULL DEFAULT 0, -- 复习总次数
  last_reviewed_at INTEGER, -- 最后复习时间戳 (可空)
  access_count INTEGER NOT NULL DEFAULT 0 -- 统计复习时的访问次数
);

-- 5. 用户设置表
-- 对应：mockSettings + SettingsPanel 所有配置
-- 设计原则：所有设置统一存为 JSON，便于结构演进无需 ALTER TABLE
CREATE TABLE IF NOT EXISTS app_settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL -- 所有设置的 JSON 表示
);

-- 6. 加密 Key 元数据表 (新增，用于 API Key 安全存储)
-- 存储 Argon2id 盐值和参数，用于派生解密 Key 的种子
CREATE TABLE IF NOT EXISTS key_metadata (
  id TEXT PRIMARY KEY DEFAULT 'master_password_salt',
  salt BLOB NOT NULL, -- 16字节随机盐值
  iterations_u32 BLOB NOT NULL, -- Argon2 迭代次数 (序列化的 u32)
  memory_cost_u32 BLOB NOT NULL, -- 内存代价 (MiB, 典型 64)
  parallelism_u8 BLOB NOT NULL, -- 并行度 (典型 2)
  created_at INTEGER NOT NULL DEFAULT (CAST(strftime('%s','now') AS INTEGER))
);

-- 7. 加密 Keys 表 (新增，存储已加密的 API Key)
-- 所有 Key 使用 AES-256-GCM 加密，需要主密码才能解密
CREATE TABLE IF NOT EXISTS encrypted_keys (
  id TEXT PRIMARY KEY,
  service_name TEXT NOT NULL, -- "google", "deepl", "baidu", "youdao"
  metadata_id TEXT NOT NULL DEFAULT 'master_password_salt',
  encrypted_payload BLOB NOT NULL, -- AES-GCM 密文 + 认证标签 (序列化 JSON)
  nonce BLOB NOT NULL, -- 12字节 Nonce (IV)
  created_at INTEGER NOT NULL DEFAULT (CAST(strftime('%s','now') AS INTEGER)),
  FOREIGN KEY (metadata_id) REFERENCES key_metadata(id)
);

-- 8. 索引：性能关键
CREATE INDEX IF NOT EXISTS idx_translation_history_timestamp
  ON translation_history(timestamp DESC);

CREATE INDEX IF NOT EXISTS idx_translation_history_favorite
  ON translation_history(favorite DESC, timestamp DESC);

CREATE INDEX IF NOT EXISTS idx_vocabulary_words_group
  ON vocabulary_words(group_id);

CREATE INDEX IF NOT EXISTS idx_vocabulary_words_word
  ON vocabulary_words(word);

-- 9. 视图：常用查询的预先定义
CREATE VIEW IF NOT EXISTS view_recent_translations AS 
SELECT id, source_text, translated_text, source_lang, target_lang, engine, timestamp, favorite
FROM translation_history 
ORDER BY timestamp DESC 
LIMIT 50;

CREATE VIEW IF NOT EXISTS view_favorite_translations AS 
SELECT * FROM translation_history 
WHERE favorite = 1 
ORDER BY timestamp DESC;
```

## 5. 安全存储设计 (API Key)

### 5.1 加密思路总结

**核心设计**：
1. **主密码派生**：用户在 Settings 设置主密码，使用 Argon2id 算法从主密码派生 32 字节关键字
2. **盐值存储**：生成 16 字节随机盐值，存储在 `key_metadata` 表中（同一数据库唯一）
3. **AES-256-GCM 加密**：使用派生出的关键字使用 `ring` 库的 AES-256-GCM 模式加密 API Key
   - GCM 模式同时提供机密性和完整性
   - Nonce (IV) 固定为 12 字节，随机生成后与密文一同存储
4. **内存零化**：使用 `zeroize` crate 确保派生的关键字、明文 Key 在函数作用域结束后立即清零防止内存转储
5. **前端零知识**：前端完全不知晓 API Key 具体值，仅通过 `translate(text)` 命令调用

**攻防场景**：
- **数据库文件被盗**：若无主密码 → 直接泄密；若有主密码 → 需要进行 Argon2id 逆向破解（计算量巨大，现实中极难）
- **内存转储**：`zeroize` 确保 Key 在函数结束后立即清零，但进程运行期间内存始终可能被访问（桌面应用基本风险）
- **Tauri IPC 捕获**：关键数据完全在 Rust 端内部处理，前端仅收到翻译文本结果

### 5.2 存储流程图

```
┌─────────────────────────────────────┐
│          用户在 Settings 输入          │
│           主密码 (主密码)               │
└───────────────────────┬───────────────┘
                      │
                      ▼
               ┌─────────────────┐
               │ Argon2id KDF     │
               │ (派生 32字节 Key) │
               └───────┬─────────┘
                       │
                       ▼
                ┌─────────────────┐
                │ AES-256-GCM 加密 │
                │ (用派生 Key)      │
                └───────┬─────────┘
                        │
                        ▼
                 ┌─────────────────┐
                 │ SQLite 加密表     │
                 │ encrypted_keys   │
                 └─────────────────┘
```

### 5.3 初始化与迁移流程

```
v0.1 (MVP，明文存储)：  
├─ init_database → 建表 + 默认 app_settings
├─ Settings 让用户输入 API Key（明文）
├─ 直接 INSERT INTO app_settings (key, value_json) VALUES ('keys', '{"google":"..."}')
└─ 备注：仅适用于个人内部使用

v0.2 (加密存储)：  
├─ 用户在 Settings 设置主密码 → 存入 key_metadata (salt)
├─ 用户重新输入/确认 API Key → store_key() 自动加密后写入 encrypted_keys
├─ 旧的明文记录保留但标记"待迁移"，新记录全部加密
└─ 备注：推荐所有用户进行一次性迁移

v0.3 (主密码保护增强)：  
├─ 用户可选择"使用主密码保护" (已在 v0.2 设置)
├─ 所有 Key 以主密码派生的种子加密
├─ 即使数据库文件被盗，也需要主密码才能解密
└─ 备注：符合合规要求的企业/商业使用场景
```

## 6. 迁移路径

### 6.1 v0.1 → v0.2 (明文 → 加密)

**步骤**：
1. 用户更新至 v0.2
2. 运行 `init_master_password` → 生成盐值 → 存入 `key_metadata`
3. 在 Settings 页面弹窗"设置主密码"
4. 用户输入主密码 → 系统读出所有明文 Key → 使用新主密码重新加密 → 写入 `encrypted_keys`
5. 标记旧记录 `is_encrypted = false` (或直接清理)
6. 前端从 `get_api_key` 改为 `translate_with_google` 等命令

**备选**（更简单）：
- 用户仅在添加新 Key 时开始加密
- 旧 Key 保持明文，新 Key 加密
- 下次打开数据库提示 "检测到明文 Key，是否现在统一迁移？"

### 6.2 v0.2 → v0.3 (增强保护)

**步骤**：
1. 用户确认 "使用主密码保护"
2. 系统重新派生 Key (相同盐值，可能不同迭代次数)
3. 所有 Key 重新加密 (或保持不变，取决于安全需求)
4. 界面提示 "你的 Key 现在受主密码保护"

## 11. Key 加密思路总结

### 11.1 核心设计哲学

**前端零知识架构**：
- 前端完全不知晓 API Key 具体值
- 仅通过 `translate(text)` 命令调用翻译服务
- Key 的生存周期完全在 Rust 端内部：存储 → 解密 → API 调用 → 零化 → 销毁

### 11.2 加密技术选型

| 环节 | 算法/库 | 理由 |
|------|----------|------|
| **密钥派生** | Argon2id (`argon2` crate) | 记忆硬化函数，抵抗 GPU/ASIC brute-force 攻击；参数（迭代=15, 内存=64MiB, 并行=2）经过了安全参数分析 |
| **内容加密** | AES-256-GCM (`ring` crate) | 认证加密模式，同时保证机密性 (Confidentiality) 和完整性 (Integrity)；GCM 模式自动附加 16 字节认证标签 |
| **随机性产生** | `ring::rand::SystemRandom` | 使用操作系统提供的密码学安全随机数生成器 (CSPRNG) |
| **内存安全** | `zeroize` crate | 在变量离开作用域前自动清零内存，防止通过 RAM dump 提取敏感信息 |

### 11.3 密钥生命周期

```
用户输入 API Key
        │
    ▼ (Rust 端)
store_key()
        │
        ├──► 用 Argon2id 从主密码派生 32字节关键字
        │        │
        │        └──► 生成 16字节随机盐值 (存于 key_metadata 表)
        │
        ├──► AES-256-GCM 加密 (用派生关键字)
        │        │
        │        ├──► 加密后密文 + 12字节 Nonce
        │        └──► 序列化为 JSON + 存入 encrypted_keys 表
        │
        └──► 旧明文立即 zeroize，仅保留密文
```

### 11.4 解密与使用流程

```
调用 translate_with_google("文本")
        │
        ├──► read_key() 从 encrypted_keys 读取密文
        │        │
        │        ├──► 读取 key_metadata 中的盐值
        │        │
        │        ├──► 用主密码 + Argon2id 派生 32字节关键字
        │        │
        │        ├──► AES-256-GCM 解密 (用派生关键字 + Nonce)
        │        │
        │        ├──► 【安全】立即 zeroize 派生关键字 + 盐值
        │        │
        │        └──► 使用明文 Key 调用 Google API
        │
        ├──► API 调用完成
        │
        ├──► 【安全】函数作用域结束，所有敏感变量自动 zeroize
        │
        └──► 返回翻译结果文本 (前端完全不知晓 Key 细节)
```

### 11.5 容错与安全边界

| 场景 | 表现 | 对策 |
|------|------|------|
| **主密码遗忘** | 所有 Key 永久无法解密 | 引导用户妥善保管主密码；在首次运行时提供 "跳过主密码保护" 选项 (明文存储警告) |
| **数据库文件泄露 (无主密码)** | 直接读取明文 (若 earlier v0.1 版本) | v0.2+：所有 Key 均加密存储，即使泄露也需 brute-force Argon2id |
| **内存转储 (RAM dump)** | 进程运行期间内存可能被访问 | `zeroize` 缩短关键数据在内存中的驻留时间；但桌面应用基本无法完全消除此风险 |
| **Tauri IPC 捕获** | 理论上可捕获进程间通信 | 关键数据完全在 Rust 端内部处理，前端仅收到翻译文本；Tauri 默认加密 IPC 通道 |
| **主密码被暴力破解** | 短弱口令易被猜出 | 引导用户设置强口令 (≥12位，包含字母/数字/特殊字符); 显示安全提示 |

### 11.6 部署注意事项

1. **`.env` 文件**：仅包含 `APP_MASTER_PASSWORD` (由运维在部署时手动设置，绝对不提交版本库)
2. **数据库文件权限**：打包后建议 `chmod 600`，仅当前用户可读写
3. **备份策略**：导出 `.db` 文件同样受主密码保护；备份前确保主密码可用
4. **Tauri 版本更新**：定期更新 `ring`, `argon2`, `zeroize` 等 crate，关注 security advisories

### 11.7 与 Prisma/SQLite 的比较

| 特性 | 原生 SQLite + 自研加密 | Prisma ORM |
|------|----------------------|-----------|
| **Key 存储位置** | 自定义 `encrypted_keys` 表 | 任意表的 JSON/TEXT 列 |
| **加密实现** | Ring + Argon2 (精细控制) | 取决于应用层实现 |
| **迁移难度** | 低 (直接 SQL 操作) | 中 (Prisma schema 变更) |
| **性能开销** | 极低 (每次调用一次加密/解密) | 取决于 ORM 的 batch 操作 |
| **前端暴露风险** | 极低 (前端零知识架构) | 取决于应用设计 |

**结论**：对于本项目，原生 SQLite + 自研加密 优于 Prisma，因为：
1. 控制力更精细 (直接控制每一次加密/解密)
2. 无额外依赖负担 (`@prisma/client` 增大 ~5MB 包体积)
3. 与 Tauri 2.x 原生集成更自然
4. 明确的安全边界 (前端零知识架构)
