## 发现的设计缺陷（来自 2026-09-09 分析）

### S级缺陷（严重）
1. **数据库设计与实现脱节**
   - 现象：`02-数据库设计.md` 已完成，但 Rust 端 `db.rs` 和 `keys.rs` 模块尚未编写
   - 影响：整个数据持久化层无法工作

2. **Mock 数据与真实数据混合**
   - 现象：`HistoryList.tsx` 直接 `import { mockTranslations }`，未定义存储抽象层
   - 影响：组件耦合 mock 数据，难以切换到真实数据源

3. **API Key 加密方案过于复杂**
   - 现象：设计了完整的 Argon2id + AES-256-GCM 方案，但 MVP 阶段可能过度设计
   - 影响：增加实现复杂度，延长开发周期

### A级缺陷（中度）
4. **Tauri 命令注册不完整**
   - 现象：`lib.rs` 中缺少 `init_database`、`add_api_key` 等关键命令
   - 影响：前端无法调用数据库初始化

5. **路径处理未标准化**
   - 现象：数据库中存储词典路径使用绝对路径，但未定义用户数据目录
   - 影响：不同操作系统下数据库文件位置不确定

### B级缺陷（轻微）
6. **缺少数据库版本管理**
   - 现象：Schema 变更后，无法判断当前数据库版本

7. **缺少错误处理和用户反馈**
   - 现象：数据库操作失败时，未定义用户可见的错误提示

## 技术决策（更新）

### 1. 数据库选型
- **选择**：原生 SQLite（非 Prisma ORM）
- **理由**：Tauri 原生支持、零依赖、单文件易迁移、性能足够
- **安全设计**：v0.1 使用明文存储（简化），v0.2 启用加密存储

### 2. API Key 存储策略
| 版本 | 方案 | 说明 |
|------|------|------|
| **v0.1** | 明文 SQLite | 降低复杂度，确保 MVP 可用；文件系统权限保护（`chmod 600`） |
| **v0.2** | 加密存储 | 引入 Argon2id + AES-256-GCM，提供一键迁移 |

### 3. 快捷键方案
- **设计原则**："首击零拦截 + 时间窗口状态机"
- **技术实现**：使用 `rdev` 库进行全局键盘监听，绕过 Tauri 原生插件限制
- **时间窗口**：默认 400ms，允许用户在设置中微调

### 4. 架构演进路径
```
v0.1 (当前) → v0.2 → v0.3 → v0.4 → v1.0
    ↓           ↓       ↓       ↓       ↓
  明文存储   加密存储  词典加载  截图OCR  正式发布
  API接入    迁移工具  词典管理  术语表    性能优化
  基础功能   功能完善  功能增强  多平台测试
```
